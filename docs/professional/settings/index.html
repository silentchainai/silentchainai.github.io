Settings & Configuration Reference

Every SILENTCHAIN Professional setting, with its default, range, and effect. Settings live in the SILENTCHAIN Professional tab under Settings, split across two tabs - AI Provider and Advanced - and persist in Burp's preferences.

Defaults philosophy

SILENTCHAIN Professional ships with safe, opt-in defaults. Passive analysis and Phase 2 active verification are both off until you enable them, the secret / PII sanitizer is on, and analysis is restricted to in-scope targets. Everything below can be tuned in the two Settings tabs; click Save to persist. The green value in the Default column is the shipped default.

Options and model names may vary by provider or software version.

AI Provider tab

Selects and configures the model that performs analysis. When Burp AI is selected, the third-party fields (URL / key / model / max tokens / Azure version) are disabled because Burp AI runs in-process. Use Test Connection to validate, and Refresh to pull the model list from providers that support it.

Advanced tab: Phase 2 Active Verification

Phase 2 actively tests injection-class findings by sending real payloads to the target and promoting confirmed findings to Certain. It is off by default and should only be run against authorized targets.

Authorized targets only. Phase 2 sends crafted payloads to the target you select. Raising concurrency and payload count increases load and the chance of a WAF IP ban - tune carefully against production systems.

Recommended presets

Local AI / restricted-network

  • AI Provider: Ollama, http://localhost:11434, a local model.
  • Ollama context (num_ctx): 8192 or higher; keep structured output on schema.
  • Sanitizer: On, as defense in depth.

Fast triage (low cost, low noise)

  • Analysis Rounds: 1. Passive: on for a focused scope only.
  • Phase 2: off - review Phase 1 findings first.
  • Max Response Size: keep the default to cap token cost.

Deep / thorough verification

  • Analysis Rounds: 2 - 3 for better recall.
  • Phase 2: on; increase payload count toward 200+ for broader verification; add Cookie and Header fuzz surfaces where appropriate.
  • Concurrency: raise cautiously (watch for WAF IP bans).
